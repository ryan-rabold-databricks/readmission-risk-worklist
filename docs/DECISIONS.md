| 6 | 2026-11-02 | Accept `account users` SELECT on `rtr_demo_catalog` as a dev-only deviation | Data is fully synthetic; revoking would break other demos in the catalog; prod uses a dedicated catalog with no account-wide grants | `databricks grants get-effective` |
| 7 | 2026-11-02 | Naming: `<source_system>_raw` / `_bronze`, `<data_domain>_silver`, `<data_product>_gold` | Scalable, intuitive layer and ownership signal in every schema name | Author's convention |

| 9 | 2026-11-02 | Synced tables live in `rtr_demo_catalog.readmission_worklist_gold` with a `_synced` suffix; no Lakebase catalog registration | Synced tables can be created in a standard UC catalog; the UC schema name becomes the Postgres schema name | docs.databricks.com/aws/en/oltp/projects/sync-tables |
| 10 | 2026-11-02 | App writes only to Lakebase `readmission_worklist_app` (`outreach_activity`, `program_setting_change`); CDF lands them in `readmission_worklist_app_bronze` | The app is a source system; landing as bronze keeps the layer suffix convention | Author decision |
| 11 | 2026-11-02 | Program Settings tab for Care Management Leadership; seed files for the initial load | Leadership owns thresholds and capacity with an audit trail, reusing the CDF pattern | Author decision |

| 13 | 2026-11-02 | Business audit events (`worklist.viewed`, `outreach.logged`, `settings.changed`, `genie.asked`) are emitted by the app; telemetry carries IDs only, never PHI | Telemetry captures sign-ins and API requests automatically, but not business actions; the landing schema is unmasked | Apps observability docs |

| 15 | 2026-11-02 | Model: XGBoost on LACE-style features, batch scored daily; `@challenger` promoted to `@champion` only if it beats AUC and calibration gates | Explainable drivers clinicians recognize; no real-time requirement | Design |
| 16 | 2026-11-02 | Dev target does not use `mode: development`; dev behaviors (paused triggers, development pipelines, max 1 concurrent run, `env` tag) are set as explicit presets | Development mode prefixes UC schemas with `dev_<user>_` even with `presets.name_prefix: ""`, which breaks the exact UC-to-Postgres schema mapping (#8). Trade-off: two developers deploying dev to the same catalog would collide | `databricks bundle validate -o json` on CLI v1.19.0 (prefixed names observed, then exact names after the change) |
| 17 | 2026-11-02 | Job code ships as one Python wheel (`readmit`, built with `uv build` as a bundle artifact); SDP pipeline and app source stay outside the wheel | One versioned package per deploy, pure logic unit-testable locally, no `sys.path` workarounds in tasks | Bundle JSON schema (`artifacts`, `python_wheel_task`, job `environments`) |
| 18 | 2026-11-02 | Environment guardrail: every job calls `readmit.common.env_guardrail.assert_environment` and fails if its catalog or Lakebase project differs from the values configured for its `env` | Implements the design's environment guardrail; a run-time parameter override cannot point dev at prod or the reverse. Trade-off: the mapping is duplicated in `databricks.yml` and the module | Design v0.4, page 2 |
| 19 | 2026-11-02 | Simulator story approved: ~16% readmit rate, Riverbend Community low 7-day follow-up and ~21% readmits, heart failure follow-up effect, winter respiratory surge, ~0.5% bad rows; JSON lines extracts; 24 months of history from 2024-11-01 | Gives the Program tab, Genie, and the model a clear, actionable signal at realistic (not perfect) separability | Author approval; story checks in `evidence/phase1/simulator_job_runs.log` |
| 20 | 2026-11-02 | Simulator randomness is hash-based Spark expressions with embedded name lists, not Faker UDFs; one catch-up mode replaces separate backfill and daily modes | Fully deterministic regardless of partitioning (the basis of idempotent reruns), no UDF Python-version coupling over Databricks Connect, pure Spark. Trade-off: less name variety | Rerun produced "nothing to do"; local dry run and job run produced identical story numbers |
| 21 | 2026-11-02 | Simulator materializes shared intermediates with `localCheckpoint()` | Without it every action re-sent the full lineage over Spark Connect (11 min dry run, oversize-proto warnings); with it 22 s locally and about 3 min for the full job. Trade-off: an executor loss fails the run instead of recomputing (task retries once) | Tested on serverless: `localCheckpoint` works, `checkpoint` fails (no checkpoint dir) |
