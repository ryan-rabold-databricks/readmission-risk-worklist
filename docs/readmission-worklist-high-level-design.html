Readmission Prevention Worklist — Recommended Operating Pattern

Eight operational steps from the nightly EHR extract to care manager outreach and measured 30-day outcomes, with the tables and assets touched in each step.

Deployment: workspace <env>_clinical_analytics • catalog <env>_care_management • Lakebase project <env>-care-management

Lakebase CDF (change data feed)

5WORK THE WORKLIST
Care Manager
Open today's prioritized list, review the drivers and brief, call the patient, and log the outcome and next step.
Readmission Worklist app(SIGN IN)
Lakebase worklist.care_worklist(READ)
Lakebase app.outreach_activity(INSERT)

READMISSION WORKLIST APP

Care managers work their list and log outreach; leadership uses the Program tab with the embedded Genie Agent. The app reads and writes Lakebase, and Genie runs on behalf of the signed-in user.

GOVERNANCE (EVERY STEP)

PHI columns carry governed tags. Tag-driven ABAC policies mask direct identifiers and filter rows by facility for every SQL, notebook, and Genie read. The Lakebase CDF landing schema stays unmasked (a CDF requirement), so only the pipeline identity can read it; policies apply from silver onward.
Ownership: red = Care Management Leadership • green = Care Manager • blue = automated Data Platform job or managed sync
Actions: READ = read only • INSERT = add rows • UPDATE = change rows • APPEND = append-only insert • UPSERT = AUTO CDC apply • MERGE = keyed upsert • REFRESH = materialized view recompute • LOAD / REGISTER / PROMOTE = UC model alias operations • LOG = MLflow run • GENERATE = ai_query call • SYNC = Delta to Lakebase synced table • CDC = Lakebase CDF to Unity Catalog • ASK = Genie question • SIGN IN = authenticated app session

PHI tagging rule
Every PHI column carries governed tag phi = direct_identifier | quasi_identifier; ABAC policies attached to the silver and gold schemas apply masks and the facility row filter automatically to new tables. lakebase_sync is excluded because CDF destinations must not carry masks or filters.
Minimum-necessary rule
Only worklist columns a care manager needs to make the call leave the lakehouse; Lakebase never holds diagnosis history or the full chart.

Readmission Worklist Entity-Relationship Diagram

Tables deployed in <env>_care_management (silver, gold) and Lakebase care_mgmt; recommended logical keys and workflow relationships.

Status, tier, type, disposition, and payer columns are controlled STRINGs. PHI marks columns carrying governed tag phi; ABAC policies mask them for non-care-team readers.
PK/FK are Unity Catalog informational constraints (not enforced); required columns are NOT NULL; jobs enforce uniqueness, idempotency, and referential checks. AK columns are hashed to generate the PK.
Every silver and gold table also carries audit_created_at / _by / _process / _run_id and audit_updated_* columns (omitted above for readability).
gold.readmission_program_metrics (metric view over readmission_outcome) defines readmission_rate, reach_rate, followup_7d_rate, and est_cost_avoided once, for Genie and the app.
